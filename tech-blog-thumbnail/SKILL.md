# 技術ブログ用サムネイル制作

画像生成ツールが利用できる場合は、サムネイル画像を制作する。`assets/yarn-to-npm-reference.png` を**デザインの参考画像**として使用する。ただし、この参考画像は公式ロゴ素材の配布元ではない。

## 入力情報

- **必須：** 記事のタイトルまたはテーマ。
- **任意：** 見出しの言語、使用する技術名やロゴ、出力先、配色、追加の参考画像。
- **初期設定：** 記事が日本語でも、画像内の見出しは**英語**にする。ユーザーから言語の指定があれば、それを優先する。

## デザイン方針

- **比率：** 横長の **1.91:1**。一般的なOGP用途では **1200×630ピクセルのPNG**を推奨する。
- **スタイル：** モダン、フラット、ミニマルな技術ブログ向けエディトリアルデザイン。白〜オフホワイトを基調とし、隅に控えめな青・ピンクの斜めのアクセントを加える。
- **文字：** 濃紺の太いサンセリフ体を使用し、縮小表示でも読める見出しにする。重要な技術名や移行先は、適切なブランドカラーで強調してよい。
- **タイトル：** 意味を保ちながら、短く自然な英語にする。長い見出しをそのまま詰め込まない。
- **副題：** 内容が重複するサブタイトルや帯状の説明文を追加しない。上部の小さなカテゴリ名は任意とし、不要なら省略する。
- **余白：** 十分な余白を取り、画像の外周におおむね **5%以上**の安全領域を確保する。
- **構図：** 移行・比較記事では、たとえば「移行元のロゴ → 右向き矢印 → 移行先のロゴ」のように関係性を直感的に示す。移行以外のテーマには、無理に矢印を使わず適切な視覚表現を選ぶ。
- **ロゴ：** 利用可能かつ利用条件を満たす場合は、**公式のロゴ素材ファイル**を使用する。AIが生成した類似ロゴを「公式ロゴ」と呼ばない。縦横比、色、余白、商標・利用ガイドラインを守る。正規の素材を確認できない場合は、その旨を明記する。
- **避ける表現：** 写真風、3D、強い影、小さすぎる文字、過剰なアイコン、透かし、ごちゃごちゃした装飾。

## 制作手順

1. 記事のテーマを読み取り、伝えるべき要点、技術名、移行や比較の方向性を整理する。
2. 意味を正確に伝える短い見出しを作成する。例：`Yarnをやめてnpmに戻す` → `Quit Yarn, Go Back to npm`。
3. 大きな見出しを上部に配置し、その下に比較図やテーマに合ったビジュアルを配置する。サムネイルとして縮小しても読めることを重視する。
4. 公式ロゴの使用が求められ、利用可能なツールがある場合は、公式配布元と利用条件を確認して素材を取得する。ロゴの画像生成よりも、正規素材の合成を優先する。
5. 利用可能な画像生成・編集ツールで制作する。Codex CLI で公式の `imagegen` Skill を利用する場合は、その Skill の手順に従う。**この Skill 自体には画像生成機能は含まれず、画像生成ツールの導入も行わない。**
6. 見出しの綴り、ロゴの再現性、矢印の向き、余白、視覚的なバランス、不要な文章の有無を確認し、必要に応じて修正する。
7. **1.91:1 のPNG**として書き出す（推奨：1200×630ピクセル）。保存先を伝え、公式ロゴの真正性を確認できなかった場合はその旨も伝える。

## プロンプトテンプレート

`references/prompt-template.md` を参照する。付属画像はデザインの方向性を示すものであり、すべての構成をそのまま再現する必要はない。

## 既存画像の修正

修正依頼では、指定されていない要素を極力変更しない。たとえば「見出しを英語にする」「副題を削除する」と指示された場合は、その部分を修正して余白を調整し、削除した副題を再追加しない。
